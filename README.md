 # Обзор диаграмм проекта «Hollow Knight: Silksong»

## Структурные диаграммы

### Class Diagram
Показывает логическую структуру игры: классы `Game`, `Hornet`, `Inventory`, `Item`, `Tool`, `Crest`, `Enemy`, `Boss`, `Quest`, `NPC`, `Map`, `SaveSystem`. Описаны атрибуты, методы и связи (ассоциация, композиция, наследование). Обоснование: выделены ключевые сущности предметной области, необходимые для реализации ФТ-1…ФТ-10.

### Component Diagram
Описывает программную архитектуру: компоненты `UI`, `GameLogic`, `MovementSystem`, `CombatSystem`, `CraftSystem`, `QuestSystem`, `SaveSystem`, `PlatformAdapter`. Показаны интерфейсы `IInput`, `IRender`, `ISave` и зависимости. Обоснование: разделение на слои UI, бизнес-логика, данные и платформенная адаптация.

### Deployment Diagram
Показывает физическое размещение: узлы PC, Xbox Series X|S, PlayStation, Nintendo Switch; артефакты `Silksong.exe` и `GamePackage`; протоколы Platform SDK / Store API. Обоснование: мультиплатформенный релиз по ТЗ.

## Поведенческие диаграммы

### Use Case
Акторы: Игрок, Платформа. Варианты использования: перемещение, бой, карта, лечение, крафт, квесты, прогрессия, гербы, быстрое перемещение, «Стальная душа», сохранение, достижения. Обоснование: покрывают все функциональные требования.

### Activity
Процесс «Бой с боссом»: вход в арену → инициализация → атака/инструмент/лечение → проверка HP → победа/поражение. Обоснование: демонстрирует ветвления и игровой цикл.

### State Machine
Объект: Хорнет. Состояния: Idle, Running, Jumping, Attacking, Dashing, Healing, Dead. Переходы по событиям ввода и игровым условиям. Обоснование: отражает жизненный цикл персонажа.

### Sequence (Cooperation)
Сценарий: атака врага с использованием инструмента. Объекты: Player, Input, GameLogic, CombatSystem, Inventory, Enemy, UI. Показана нумерованная последовательность сообщений. Обоснование: демонстрирует взаимодействие компонентов.

## Функциональные диаграммы

### IDEF0 A-0
Контекстная диаграмма: цель — описать процесс разработки игры; точка зрения — руководитель проекта. Входы, управления, выходы, механизмы.

### IDEF0 A0
Декомпозиция на A1 (проектирование мира и механик), A2 (разработка контента и квестов), A3 (тестирование и балансировка), A4 (локализация, релиз, поддержка).

### DFD уровень 0
Контекстная диаграмма: игровой процесс, внешние сущности «Игрок» и «Платформа», потоки данных.

### DFD уровень 1
Декомпозиция процессов: P1 (перемещение), P2 (бой), P3 (прогрессия и крафт), P4 (квесты и карта). Хранилища D1–D3.
